# MuseOS

[English](README.md) · 简体中文 · [Français](README.fr.md)

> 一个想法进来，多个 AI 模型并行工作，一份整合后的结果出来。

MuseOS 是一个在你自己电脑上运行的多模型编排引擎，用的是**你自己的模型**：Chief 先确认目标，把想法拆成任务，
分给不同模型并行执行，可选一轮交叉审查，最后合成一份结论，并列出共识、分歧、假设、风险和局限。
它还自带**盲测**：同一个问题另外交给单个模型回答，两份答案不署名，你来投票，用自己的问题验证多模型到底有没有用。

完整的技术说明、接口、配置和测试见英文版 [README.md](README.md)。本文件是日常使用指南。

## 使用方法（日常使用）

**1. 安装和启动。** 需要 Python 3.12+ 和 [uv](https://docs.astral.sh/uv/)，不用装数据库。

```bash
git clone https://github.com/Tooonnnnyyy/museos.git && cd museos
```

```bash
uv sync
```

```bash
uv run museos serve
```

打开 http://127.0.0.1:8000 。没有任何配置时是**演示模式**，用内置的模拟模型，回答是占位文字。

**接入你自己的模型：**

```bash
uv run museos setup
```

每个模型运行一次。它会问你类型，用隐藏输入读取 key，能验证的会验证，然后写好 `providers.toml` 和 `.env`。接两个以上不同的模型效果最好。

| 你有什么 | 在 setup 里选 | 说明 |
|---|---|---|
| OpenAI、Anthropic、Google、DeepSeek、xAI 的 API key | 对应的供应商 | 由供应商按量计费 |
| OpenRouter 的 key | OpenRouter | 一个 key 可以用很多家的模型 |
| 通义千问、Kimi、智谱、公司网关、本地 Ollama 等 | Any OpenAI-compatible endpoint | 填 Base URL 和模型 ID |
| Claude Pro/Max 订阅 | Claude subscription | 用你自己的登录运行官方 Claude Code CLI，仅限个人使用 |
| 其他已登录的命令行工具 | Another command-line tool | 填命令；它从标准输入读问题，把回答打印出来 |

模型 ID 需要你自己填，因为它经常变，请从供应商的模型页面复制。ChatGPT Plus 这类 App 订阅不是 API key。

**关于订阅：** 个人订阅只供你自己使用。MuseOS 运行的是厂商自己的工具，不读取也不保存你的登录信息，一次只发一个请求，并限制每次运行和每天的调用次数。不要把订阅接到给别人用的服务上，那种情况请用 API key。遵守供应商条款是你自己的责任。

**2. 提交一个想法。** 在页面顶部写下想法，点「开始」。三个开关：

| 开关 | 作用 | 什么时候开 |
|---|---|---|
| 先问清楚再分发 | Chief 先把你的想法改写成一句目标，最多问 3 个问题。你答完（或跳过）才开始分任务 | 默认开。想法还模糊时最有用 |
| 交叉审查 | 每个 Agent 的结果由另一个模型挑毛病 | 默认开。想省钱省时间可以关 |
| 盲测 | 同一个问题另外交给单个模型独立回答，两份答案不署名并排显示，你投票 | 验证期每个真实想法都开 |

**3. 回答 Chief 的问题。** 页面会出现一张便签。能答的答一句，不想答的留空，留空的按便签下方列出的假设处理。

**4. 读结果。** 先看摘要、共识、分歧、下一步。分歧是最值得你花时间的地方。每个 Agent 的原始输出、假设、风险、局限都可以展开。

**5. 盲测投票。** 开了盲测的任务不显示过程。两边都完成后页面显示 A 和 B，选更有用的一份，投票后才揭晓哪份是多模型合成。
黄色横条累计战绩：投满 10 次，MuseOS 赢 6 次以上算通过；否则应该把系统简化成「一问多答 + 一键合成」。

**小请求不动用团队。** 开着「先问清楚」时，Chief 会先判断请求类型：简单问题由一个模型直接回答；要求它动手做事（打开、发送、安装）的请求，会直接说明 MuseOS 不能执行操作，并给出你可以自己运行的步骤；只有真正的项目想法才分给团队。

**后台页面。** http://127.0.0.1:8000/admin 显示每个模型的用量、费用和失败记录、最近 14 天的花费，以及当前设置。除了「重试被暂停的模型」之外都是只读的。Key 只显示有或没有。

**语言。** 页面、模型的回答和系统自己写的说明都支持英文、法文和简体中文。用顶部的 `EN / FR / 中文` 切换：它同时决定页面语言和下一次运行的输出语言，不管想法是用什么语言写的。已经完成的运行保持当时的语言。API 里传 `"language": "en" | "fr" | "zh"`，命令行用 `--lang`。不指定时，模型跟随想法的语言。

**命令行用法**（不开网页时）：

```bash
uv run museos run "你的想法" --clarify --cross-review --lang zh --budget 0.5 --out artifacts/idea.md
```

**花费和限制：**
- 费用直接付给你的模型供应商。一次带交叉审查的运行通常是 8 到 12 次模型调用，用小模型的话是几美分。每个任务都会显示 token 和费用。
- 每次运行的预算上限默认 $2，服务端强制，页面上填再多也不会超过。
- 订阅类模型默认一次只发一个请求，每次运行最多 6 次、每天最多 40 次，超了自动改用其他模型。
- 服务只接受本机访问，没有登录。不要把端口暴露到公网。
